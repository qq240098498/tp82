# tp82 依赖台账与版本核查平台

一个本地小工具：把各个项目用到的依赖集中登记起来。页面上先建项目，再往项目下面登记依赖名称、版本、许可、责任人与状态；同一个依赖被两个项目用到时，版本高低一眼能比出来。依赖名写得不合规矩、版本不是三段数字、同一个项目里重复登记同一个依赖，保存时当场就会指出来。

版本对照区把散落在各个项目里的同一条依赖摆到一张表上：一共被几个项目用过、分别是什么版本、哪些版本彼此不一致。不一致的可以下钻到每个项目的具体登记条目，并一键预演「统一到某个版本」会改动哪些登记、各从什么版本改成什么版本，确认后才真正执行；执行后会列出本次改了哪些项目。推荐统一到使用项目最多的版本，版本之间的高低关系与差在第几段数字都会写明。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5082>

端口固定为 `5082`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，新建登记时会把它带进责任人
2. 项目区列出项目名称、负责人、说明与这个项目下已经登记了多少条依赖；可以新增项目，也可以改名、换负责人、删除
3. 依赖登记区顶部可以按项目、状态、许可筛选，再按依赖名、责任人或者备注搜索，右上角刷新按钮重新拉取一次
4. 点新建登记，选好所属项目，填上依赖名称、版本，按需要补许可、责任人、状态与备注；列表里点编辑会把这条登记回填到表单
5. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除项目与删除登记都会先确认
6. 版本对照区按依赖名汇总：每行显示这条依赖被几个项目使用、共几条登记，以及各个版本分别有几个项目在用，版本按从低到高排列；版本不一致的行排在最前面，并标明最低与最高版本差在第几段数字（主版本号、次版本号或修订号）
7. 点查看明细可以下钻到这条依赖在每个项目里的具体登记条目（项目、登记编号、版本、状态、许可、责任人、备注、更新时间）
8. 明细下方选择要统一到的版本（默认选中推荐版本），点先做预演：弹层列出哪些项目的哪条登记需要改、从什么版本改成什么版本、与目标版本的高低关系；预演不写任何数据
9. 在弹层里确认执行统一后才真正落盘，页面给出回执：本次改了哪几个项目、各从什么版本改成什么版本；不需要改的登记保持不动

推荐哪个版本更稳妥：以「使用项目最多」为准——统一到多数派版本影响面最小；使用项目数并列时按就高原则取版本较高的那个，页面会写出具体依据。

项目下面还挂着依赖登记时不允许删除项目，页面上会写清还剩多少条、例如哪几条，先处理这些登记再删。

## 登记口径

- 依赖名称以小写字母或数字开头，可以用小写字母、数字、点、下划线、短横线与斜线，最长 60 个字符；带范围的写法例如 `@types/node` 也按这个口径登记
- 版本写成三段数字，例如 `2.7.18`，需要时可以带一段预发布后缀，例如 `5.0.10-rc.1`
- 许可按实际名称填写，例如 `MIT`、`Apache-2.0`、`BSD-3-Clause`；还没确认的可以留空，列表里会显示成未填
- 责任人可以留空，表示这条依赖还没有定人
- 状态只有三种：在用、待升、已弃用
- 备注用来写为什么用这个版本、有没有待办，最长 200 个字符
- 同一个项目下不允许出现同名的依赖，同一个依赖在不同项目里各登记各的、互不覆盖

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "projects": [...], "deps": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径                | 说明                                             |
| ------ | ------------------- | ------------------------------------------------ |
| GET    | /api/health         | 服务状态检查                                     |
| GET    | /api/projects       | 项目清单，附带每个项目的依赖条数                 |
| POST   | /api/projects       | 新增项目                                         |
| PATCH  | /api/projects/:id   | 修改项目的名称、负责人或说明                     |
| DELETE | /api/projects/:id   | 删除项目                                         |
| GET    | /api/deps           | 依赖登记列表，支持按项目、状态、许可筛选与关键词搜索 |
| POST   | /api/deps           | 新增依赖登记                                     |
| GET    | /api/deps/:id       | 查看单条依赖登记                                 |
| PATCH  | /api/deps/:id       | 修改依赖登记                                     |
| DELETE | /api/deps/:id       | 删除依赖登记                                     |
| GET    | /api/consistency    | 按依赖汇总版本分布，支持 keyword 与 onlyInconsistent 筛选 |
| GET    | /api/consistency/:name | 下钻某条依赖在各项目里的具体登记条目          |
| POST   | /api/consistency/preview | 统一版本预演，返回将要改动的登记清单（不落盘） |
| POST   | /api/consistency/unify | 执行统一版本，需带 `{ "confirmed": true }`     |

统一预演与执行的请求体均为 `{ "name": "spring-boot", "version": "2.7.18" }`；执行时再带 `"confirmed": true`。预演/执行结果里每条改动包含项目、登记编号、原版本、目标版本，以及 `relation`（高低关系与差在第几段数字）。执行结果另外返回本次实际改动条数、原本已是目标版本的条数与执行时间。

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
